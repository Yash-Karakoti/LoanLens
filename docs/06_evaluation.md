# Model evaluation

Generated by `python -m src.evaluate`. The saved model and decision threshold were frozen before this evaluation. No model, feature, parameter or threshold was changed using the holdout.

## Model selection

**Best model: Decision Tree / class_weight because it ranked first by training five-fold stratified CV approval-class F1, with ROC-AUC as the predefined tie-breaker.** Its selected mean CV F1 is **0.869626** (fold standard deviation 0.027836); CV ROC-AUC is **0.683752**. Parameters: `{"model__max_depth": 2, "model__min_samples_leaf": 5}`. Best means best under this search and selection criterion, not universally best, best on all metrics, or proven superior statistically.

Each of the five requested algorithms was compared under class weights and SMOTENC with randomized search on training-only folds. The independent final split contains **491 training applications** and **123 holdout applications**. The positive class is historical approval Y=1. Baseline is an actual `DummyClassifier(strategy='most_frequent')` fitted only on training labels.

Precision, recall and F1 refer to approvals. `macro_f1` weights both classes equally; `rejection_recall` is the fraction of historically rejected cases correctly rejected. Balanced accuracy averages the two class recalls. Average precision summarizes the PR curve. Brier score measures probability squared error (lower is better), but is not a complete calibration validation. The score is a model estimate, not an established real-world probability.

The apparent training minus holdout accuracy gap is **-0.079662**; the F1 gap is **-0.048524**. Apparent training scores are optimistic in-sample measurements. A small/negative gap does not establish generalization, especially with this small holdout. These gaps compare the same standard 0.5 policy.

## Business-cost threshold demonstration

The assumed scenario cost is **5 units per false approval** and **1 per false rejection**. The threshold **0.76** was selected using training out-of-fold probabilities, never holdout labels. Holdout scenario cost is **58 at 0.5** and **85 at 0.76**, a change of **+27 units**. A training-selected threshold can perform worse on unseen rows; the reported values remain as measured. The application uses the training-selected policy, while the standard metrics remain visible for comparison. These costs are assumptions, not actual financial/default losses.

At that selected threshold, training OOF predictions approve **0** of **491** rows, with scenario cost **337**. The tuned policy approves **0** of **123** holdout rows. A reject-all result can minimize this assumed cost while failing the practical shortlisting objective; it must not be presented as successful screening. Class weighting changes fitted probability estimates, and the scores have not been recalibrated. A meaningful operating policy needs independently justified costs and further training/validation evidence rather than a threshold changed after seeing this holdout.

Hyperparameters and model family were selected with the same training folds later used to create threshold-tuning out-of-fold predictions. Those OOF predictions therefore retain model-selection optimism; this is not nested CV. Holdout results are final evaluation, not another optimization target.

## Evidence and limits

Plots: `confusion_matrix.png`, `confusion_matrix_tuned.png`, `roc_curve.png`, `pr_curve.png` and `threshold_cost.png` under `reports/figures`. The cost plot uses training OOF data; ROC/PR curves and matrices use the holdout.

This dataset contains decisions rather than repayment/default outcomes; no conclusion about NPA reduction or verified creditworthiness follows. The collection date, deployment distribution and complete lending policy are unknown. The holdout is small and one random split is not external validation. Substantial production work would require richer consented data, calibrated/validated scores, uncertainty assessment, documented policy and human governance. These are limitations, not unimplemented claims of this college prototype.
